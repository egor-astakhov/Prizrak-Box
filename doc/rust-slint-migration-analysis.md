# Миграция фронтенда на нативный UI (без web-движка): анализ и выбор платформы

> Контекст: Electron (`src-electron` + Vue в `src/`) → Wails v3 (`src-wails`, тот же Vue
> во WebView) → **нативный UI без каких-либо web-элементов**. Бэкенд `px` (`src-go`) и
> `px-service` (`src-service`) остаются без изменений: новая оболочка говорит с ними по
> тем же контрактам, что и Wails (`/pxStore`, `/pxAlive`, REST + WebSocket `px`,
> IPC-сокет/named pipe `px-service`).

## 1. Требования, которые определяют выбор

| Требование | Что из него следует |
|---|---|
| Никаких WebView/HTML/CSS-движков | Tauri, Wails, Electron, Dioxus-desktop, Neutralino и т. п. исключены |
| Идентичный интерфейс (полупрозрачные панели поверх картинки-фона, акцент из картинки, тёмная/светлая тема, скругления 8/12/999, пилюли, модалки со «скримом», тосты) | Нужен **полностью кастомный рендер** (не нативные контролы ОС), с прозрачностью, градиентами, клиппингом, тенями |
| Windows: кастомный заголовок с 4 кнопками (в трей / свернуть / развернуть / закрыть), macOS: «светофор» + 1 кнопка, Linux: 4 кнопки | Безрамочное окно + программный drag/resize; на macOS — full-size content view со скрытым заголовком |
| Рабочий трей (режимы, группы прокси с radio, дашборды, System Proxy/TUN, иконка с бейджем на Windows, template-иконка на macOS) | Нативный трей с динамическим меню (tray-icon + muda) |
| Иконки процессов в «Соединениях» | Доступ к Win32 / AppKit / freedesktop из того же процесса |
| Глобальный хоткей, автозапуск, deep links `prizrak-box://`, single instance, уведомления | Зрелая системная экосистема языка |
| Win / macOS / Linux × x64 / arm64 | Кросс-компиляция в GitHub Actions |
| Лицензия проекта GPL-3.0 | Нужна совместимая лицензия UI-тулкита |

## 2. Кандидаты

| Вариант | Рендер / стилизация | Плюсы | Минусы для нас | Итог |
|---|---|---|---|---|
| **Rust + Slint 1.18** | Декларативный DSL (`.slint`), Skia/FemtoVG/software, полностью кастомные компоненты, анимации, `clip`, `opacity`, градиенты, тени, `Path`/SVG, глобальные палитры | Самый близкий к CSS-подходу декларативный язык; компилируется в нативный код; GPL-3 совместим (Slint GPLv3/royalty-free); есть живой продакшн-пример в нашей же нише — [fatyzzz/multicore](https://github.com/fatyzzz/multicore) (Rust+Slint, mihomo, трей на tray-icon); стабильный API 1.x; доступ к winit для macOS hidden-inset и безрамочного окна | Нет `backdrop-filter` (размытие под панелями) — решаем предблюром картинки фона и её «прорезанием» внутри панелей; нет inline-flow для rich-text — решаем сегментами | **Выбран** |
| Rust + iced 0.13 | Elm-архитектура, wgpu | Чистая модель состояния | Слабая кастомизация стилей (каждый виджет — свой Style-trait), нет готовых анимаций, тени/блюр ограничены; на идентичный CSS-дизайн уйдёт заметно больше кода | Хуже |
| Rust + egui | Immediate-mode | Очень быстрый старт | Пиксель-в-пиксель дизайн с прозрачностью/скруглениями/анимациями — тяжело; непривычная «игровая» модель для сложных форм | Хуже |
| Rust + GPUI (Zed) | Tailwind-подобный API, GPU | Мощно, быстрый текст | Не опубликован как стабильный crate, Windows-порт молодой, нет трея/меню, API ломается | Риск |
| Rust + Freya (Dioxus+Skia) / Blitz | Dioxus-модель / нативный HTML-CSS рендер | Можно перенести часть вёрстки | pre-1.0, Blitz по сути — снова HTML/CSS-движок (противоречит «без web») | Риск |
| Qt / QML (cxx-qt) | QML | Очень зрелый | Тяжёлый рантайм (~40–80 МБ), LGPL-нюансы, C++-тулчейн во всех CI-джобах | Избыточно |
| Flutter | Skia/Impeller | Хороший кастом-UI | Dart-рантайм, тяжёлый, трей/хоткеи через плагины, второй язык | Избыточно |

## 3. Решение

**Rust + Slint** (`slint = 1.18`, backend winit, renderer Skia c fallback на software).
Причины: декларативная вёрстка, позволяющая повторить CSS-макет 1:1; нативный код без
web-движка; все системные куски (трей, хоткей, автозапуск, deep links, single instance,
иконки процессов, уведомления, диалоги) закрываются зрелыми crate'ами
(`tray-icon`/`muda`, `global-hotkey`, `rfd`, `notify-rust`, `objc2-*`, `windows`);
пример multicore подтверждает, что стек выдерживает продакшн в нашей нише.

### Как закрываются «трудные» места дизайна

* **Размытие под панелями (`backdrop-filter: blur`)** — фон статичен (cover), поэтому
  Rust заранее строит размытую копию фона (радиус = «Размытие» из диалога темы) и
  каждая полупрозрачная панель рисует внутри себя фрагмент этой копии, выровненный по
  абсолютным координатам окна. Визуально идентично CSS-backdrop.
* **Акцент из картинки, авто светлая/тёмная** — 1:1 порт `util/theme.ts`
  (`analyzeImage`, `accentFor`, `onColor`) на Rust поверх декодированных пикселей; тут
  даже лучше, чем во WebView: нет «tainted canvas», поэтому акцент считается для любых
  удалённых картинок без прокси.
* **Заголовок окна** — Windows/Linux: `no-frame` окно, 4 кнопки (в трей, свернуть,
  развернуть/восстановить, закрыть-выйти), drag через winit `drag_window()`, resize через
  `drag_resize_window()`. macOS: `titlebar_transparent + fullsize_content_view`,
  нативный «светофор» + одна кнопка «в трей» (как в Wails/Electron).
* **Шрифт с флагами на Windows** — тот же `TwemojiCountryFlags`, сконвертированный в TTF
  и встроенный в бинарник.

## 4. Архитектура `src-rs`

```
src-rs/
  Cargo.toml, build.rs           (slint-build, ресурсы Windows, иконки)
  ui/                            (.slint: тема, базовые компоненты, страницы, оверлеи)
  src/
    main.rs                      (запуск, single instance, deep link, event loop)
    paths.rs                     (порт internal/locate: HomeDir, флаги, бинарники)
    core.rs                      (порт CoreService: callback-сервер /pxStore,/pxAlive, спавн px)
    tun.rs                       (порт TunService: IPC px-service, эскалация, состояние службы)
    api.rs, ws.rs                (REST/WebSocket px — порт src/api/*)
    store.rs, migrate.rs         (px-electron.db/config.json + миграция Electron/Wails/1.0.20)
    i18n.rs                      (src/locales/*.yaml встраиваются при сборке)
    theme.rs                     (порт useAppTheme/theme.ts, блюр фона)
    tray.rs, hotkey.rs, autostart.rs, fileicon.rs, notify.rs, deeplink.rs, single_instance.rs
    app/*.rs                     (контроллеры страниц: Home, Proxies, Profiles, Settings…)
```

## 5. Совместимость и миграция

* Данные `px` — тот же каталог `~/Prizrak-Box-V3` (или переопределённый через
  `<UserConfigDir>/prizrak-box/home.path`), тот же `px -addr=… -home=…`.
* Настройки UI — тот же файл `<home>/px-electron.db/config.json` (формат
  electron-store/kvstore: ключ → JSON-строка pinia-стора), т. е. переход Wails → Rust и
  обратно сохраняет тему, язык, порт, хоткей и т. д.
* Флаги оболочки (`start-minimized`, `tun-desired`, `dark-bg`, `home.path`) — те же
  файлы в `<UserConfigDir>/prizrak-box/`.
* Автозапуск: Windows — та же задача планировщика «Prizrak-Box Startup» (и чистка
  старого Run-ключа Electron), macOS — LaunchAgent/SMAppService на тот же bundle id,
  Linux — тот же `~/.config/autostart/prizrak-box.desktop`.
* Пакеты/репозитории: тот же bundle id `com.legiz-ru.prizrak-box`, то же имя приложения
  и пути установки (`/Applications/Prizrak-Box.app`, `%LOCALAPPDATA%\Programs\Prizrak-Box`,
  `/usr/bin/prizrak-box` + `/usr/lib/prizrak-box`), поэтому установка Rust-сборки поверх
  Electron/Wails/1.0.20 заменяет их без ручных шагов.

## 6. Состояние реализации (src-rs)

Готово и проверено на macOS с живым `px` (снимки окна через `PRIZRAK_SNAPSHOT_DIR`):

* каркас окна: сайдбар (бренд/лого профиля, навигация, режимы Rule/Global/Direct с
  правилом `global-mode: false`, Proxy/TUN с пульсацией, язык/тема/выход), шапка с
  выбором группы/прокси, кнопки окна по ОС (macOS — «светофор» + «в трей»;
  Windows/Linux — 4 кнопки, перетаскивание, ресайз, двойной клик = развернуть);
* темы: тёмная/светлая/авто (по картинке или ОС), 12 фонов из `theme.json`, своя
  картинка, прозрачность/размытие/затемнение, акцент из картинки, тема профиля
  `pxd-theme` с блокировками, эмуляция `backdrop-filter`;
* «Главная» (приветствие, карточка профиля, объявления с цветами, продление,
  IP/система), «Прокси» (группы, сетка узлов, тесты задержки, Smart-веса, скрытие,
  сортировка, переход к группе), «Профили» (мультивыбор, редактирование, ТВ,
  объявления, удаление, перетаскивание порядка через `/profile/order`),
  «Настройки» (приложение, ядро, DNS-редактор, хоткей, age-ключи, панели, DNS-запрос,
  служба TUN), «Правила» (текущие/шаблоны/провайдеры/исключения), «Соединения»
  (список, sankey-топология, процессы с иконками приложений, детали), «Журнал»;
* трей (tray-icon), глобальный хоткей, автозапуск, deep links, single instance,
  уведомления (обновления, напоминания о подписке), проверка обновлений;
* миграция (см. §5) и упаковка: `.app`/DMG (тот же `create-macos-dmg.mjs`),
  MSI (тот же `installer/build-msi.js`, цепочка продукта Wails, вытесняет
  Electron), deb/rpm/Arch (nfpm, то же имя пакета `prizrak-box`).

Windows и Linux: код проходит проверку типов (`cargo xwin check`, кросс-`check`),
сборка и пакеты собираются в CI (`release.yml` → `build_*_rs`, `rs-build.yml`).

Известные отличия от web-версии:

* перетаскивание файла из проводника прямо в окно — Slint не отдаёт внешние
  drop-события; вместо этого работает тот же оверлей «Открыть файл»;
* YAML-редакторы (DNS, шаблоны правил, просмотр провайдера) повторяют Ace
  (цвета tomorrow / tomorrow_night, колонка номеров строк, межстрочный интервал,
  без переноса строк), но без подсветки синтаксиса;
* размытие под диалогами (`--scrim-blur`) — снимок окна без оверлеев,
  размытый в Rust (≈50 мс в release при открытии), а не «живой» фильтр: под
  открытым диалогом фон не обновляется (кроме диалога темы — там снимок
  пересоздаётся после смены оформления);
* клик по системному уведомлению о подписке открывает диалог на всех ОС
  (Linux — D-Bus, macOS — NSUserNotificationCenter, Windows — тост под тем же
  AppUserModelID «Prizrak-Box», что у Wails), но только пока баннер на экране и
  приложение запущено: из Центра уведомлений / после перезапуска (как у Wails
  через UNUserNotificationCenter / COM-активатор) клик не обрабатывается;
* шрифт: системный, как `-apple-system` / `Segoe UI` у web-версии (на macOS
  SF, на Windows Segoe UI после Twemoji с флагами). На macOS у SF рисуется
  «дисплейное» начертание (opsz 28): Slint не применяет оптический размер,
  а браузер берёт «текстовое» — мелкий текст в Rust примерно на 5–7 % уже;
* Snap Layouts поверх кнопки «развернуть» (WebView2 non-client regions) на
  безрамочном окне winit недоступны.
